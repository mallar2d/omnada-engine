# Дорожня карта проєкту (робоча назва — TBD)

> Чернетка. Мова — українська; перед публічним анонсом перекласти англійською.

## 1. Що ми робимо і для кого

**Продукт:** безкоштовний open-source рушій (форк Godot, MIT) з візуальним програмуванням
у стилі Construct — **у 2D і в 3D**.

**Користувач:** дорослі люди, які хочуть робити ігри, але не вміють і не хочуть писати код
і не хочуть «вайбкодити» з AI. Вони хочуть **розуміти й контролювати** логіку своєї гри.

**Головна перевага:** event sheets для 3D. У Construct 3D немає, а в Godot є потужний 3D,
але до нього потрібен код. Ми закриваємо цю діру.

**Позиціонування:** «Твоя гра — твоя логіка. Видно кожне правило, нічого не згенеровано за тебе».

## 2. Принципи

1. **Тонкий форк.** Весь функціонал — у `modules/` та вбудованих плагінах. Патчі ядра — лише
   окремими маленькими комітами з префіксом `[core-patch]`, щоб їх легко знайти при оновленні.
2. **Сумісність.** GDScript, сцени, GDExtension, звичайні Godot-проєкти мають працювати.
3. **2D і 3D рівноправні.** Ядро event sheets не знає про вимір; 2D/3D відрізняються лише
   набором дій/умов і behaviors.
4. **Нічого не захардкоджено англійською.** Усі нові рядки інтерфейсу — через `TTR()`/`tr()`.
5. **Модульність заради спільноти.** Кожен behavior, ефект або набір дій — окремий
   незалежний шматок, який новий контриб'ютор може зробити, не розбираючись у всьому проєкті.

## 3. Як поняття Construct лягають на Godot (чернетка, деталізувати в етапі 1)

| Construct | Godot | Примітка |
|---|---|---|
| Layout | Сцена-рівень | 2D або 3D |
| Layer | `CanvasLayer` (2D) / не потрібно (3D) | |
| Object type | Сцена `.tscn` (+ автогрупа з її назвою) | «Тип» для користувача = сцена |
| Instance | Нода-інстанс сцени | |
| Family | Група Godot | |
| Instance variables | `@export`-змінні кореневої ноди | редагуються в інспекторі |
| Global variables | Автозавантаження (autoload) | |
| Behavior | Дочірня нода-компонент | додає свої дії/умови в аркуш |
| Effect | Згенерований `ShaderMaterial` | |
| Event sheet | Ресурс → компілюється в `.gd` | згенерований код лише для читання |

## 4. Архітектура (верхній рівень)

```
ACE-реєстр (Actions / Conditions / Expressions) — єдиний «словник»
   ├── вручну описані ACE (красиві назви, іконки, категорії)
   ├── автогенеровані з ClassDB
   ├── ACE від behaviors
   └── ACE від ефектів
Event sheet (ресурс) ──компілятор──> GDScript (+ карта «рядок коду → подія» для помилок)
Picking: список вибраних інстансів на кожну подію; вкладені події його успадковують
```

Ключові відкриті питання для специфікації: `Else`, `For each`, `Trigger once`, `Wait`
(зберігає вибраних), picking двох типів одночасно (зіткнення), тригери → сигнали,
звичайні умови → `_process`/`_physics_process`.

## 5. Будь-який жанр, а не «конструктор платформерів»

Ядро (event sheets, picking, змінні, компілятор) **не знає нічого про жанри**. Жанр живе лише
в behaviors, шаблонах і прикладах. Що можна зробити, визначає набір можливостей (ACE),
а не те, під яку гру ми робили першу демку.

### 5.1 Карта можливостей

| Група | Що входить | Етап |

### 5.3 Коли готового немає

- **Автогенерація з ClassDB** відкриває *будь-яку* можливість Godot, навіть без гарної назви.
- **Розширення:** плагін (або учасник спільноти) може додати свої дії, умови й behaviors.
- **«Аварійний люк»:** блок «Виконати GDScript» і власні GDScript-функції, які видно в аркуші
  як дії. Для тих, хто колись захоче трохи коду. Обов'язковим він не стає.

## 6. Етапи

### Етап 0 — Фундамент
- База: `master` (4.8-beta); перейти на `4.8-stable`, щойно вийде, далі — тільки стабільні гілки.
- Remote `upstream` на godotengine/godot, регулярні мерджі.
- Збірка редактора локально (`scons platform=linuxbsd target=editor`).
- CI: залишити лише Linux/Windows/macOS-збірки редактора, решту воркфлоу вимкнути.
- Ребрендинг: назва, `version.py`, іконка, сплеш (копірайт і ліцензію Godot зберегти).
- **Готово, коли:** CI збирає перейменований редактор під 3 ОС.

### Етап 1 — Дизайн-документи (до коду)
- ⬜ `docs/design/mapping.md` — таблиця з розділу 3, остаточна.
- 📝 `docs/design/ace-format.md` — формат опису однієї дії/умови/виразу (чернетка v0.1).
- 📝 `docs/design/picking.md` — семантика picking і у що компілюється кожна конструкція (чернетка v0.1).
- 📝 `docs/design/expressions.md` — мова виразів у полях параметрів (чернетка v0.1).
- 📝 `docs/design/sheet-format.md` — формат файлу аркуша (чернетка v0.1).
- **Готово, коли:** можна вручну «скомпілювати» на папері приклад з 10 подій.

### Етап 2 — Прототип event sheets (GDScript-плагін)
- Таблиця подій: умови → дії, вкладені події, групи, коментарі, змінні.
- ~60 вручну описаних ACE з груп «Ввід», «Об'єкти», «Змінні й дані» (включно з масивами
  й словниками), «Логіка», базові зіткнення (§5.1).
- Компілятор у GDScript + picking + показ помилок на рядку аркуша.
- **Готово, коли:** без коду можна зробити 2D-збирайку монет, 3D-збирайку монет і
  головоломку на сітці (еталонна гра 4). Остання доводить, що ядро не прив'язане до фізики.

### Етап 3 — Behaviors (2D + 3D) і експорт
- 2D: Platformer, 8Direction, Bullet, Solid, Sine, Rotate, Fade, Destroy outside.
- 3D: Character (від першої/третьої особи), Orbit camera, Follow camera, Bullet3D, Rotate, Sine, Physics.
- Можливості етапу 3 з карти §5.1: навігація, TileMap/GridMap, анімація, UI, звук, збереження.
- Автогенерація ACE з ClassDB (базова, без гарних назв). Це страховка, щоб жоден жанр не впирався в стелю.
- Export templates під Windows/Linux/macOS/Web.
- **Готово, коли:** еталонні ігри 1–5 (§5.2) зроблені без коду і збираються в `.exe`/web.
- 🎯 **Публічний анонс:** відео «3D-гра без коду за 15 хвилин», README, Discord, good-first-issues.

### Етап 4 — Новий вигляд і спрощений редактор
- Нова тема редактора (кольори, шрифти, відступи) + власний набір іконок.
- Профіль редактора за замовчуванням: сховати зайві доки/ноди/налаштування; режим «Експерт» вертає все.
- Стартовий екран і менеджер проєктів з шаблонами — еталонні ігри з §5.2.
- Простий 3D-конструктор рівнів: примітиви (CSG), прилипання до сітки, готові набори асетів (CC0, напр. Kenney).
- Зміни розкладки — лише там, де без патчу ядра ніяк.

### Етап 5 — Розширення
- Автогенерація ACE з ClassDB: людські назви, іконки й категорії для популярних.
- Еталонні ігри 6–11 (§5.2).
- Стек шейдерних ефектів (2D і 3D): Glow, Outline, Wave, Pixelate, Color Replace, Dissolve…
- Редактор виразів з автодоповненням.
- Налагоджувач аркушів: точки зупинки на подіях, перегляд вибраних інстансів.
