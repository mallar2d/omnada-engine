# Дизайн: формат файлу event sheet

> Статус: **чернетка v0.1**. Етап 1 дорожньої карти (`docs/ROADMAP.md`).
> Пов'язані документи: `picking.md`, `ace-format.md`, `expressions.md`.

## 0. Простими словами

Аркуш подій зберігається в текстовому файлі `.eventsheet`. Це звичайний текст (JSON), тож:
- зміни видно в git, і їх можна переглянути в pull request;
- шматок аркуша можна скопіювати в Discord чи на форум, і інший користувач вставить його
  у свій аркуш (як у Construct);
- якщо плагін не встановлено або файл з новішої версії, **нічого не губиться**.

Згенерований GDScript **не зберігається** як окремий файл проєкту. Він завжди виходить з аркуша,
тож розсинхронізація неможлива. Подивитися його можна кнопкою «Показати код».

## 1. Вимоги

1. **Читабельні diff.** Зміна одного параметра — один змінений рядок. Переміщення події —
   змінюються лише рядки цієї події.
2. **Стабільність.** Відкрив і зберіг без змін — файл байт у байт той самий.
3. **Нічого не губиться.** Невідомі ACE, поля й блоки зберігаються як є.
4. **Інтеграція з Godot.** Переміщення й перейменування сцен, звуків та інших файлів у Godot
   оновлює посилання в аркуші. Експорт гри знаходить усі залежності.
5. **Версії формату.** Старі файли відкриваються й мігрують. Новіші відкриваються лише для
   читання, з попередженням.
6. **Буфер обміну = той самий формат.** Скопійовані події — це фрагмент того самого JSON.

## 2. Чому JSON

| Варіант | Плюси | Мінуси |
|---|---|---|
| `.tres` (ресурс Godot) | нативний, нічого писати не треба | дерево подій розкладається на плаский список під-ресурсів з id; diff важко читати |
| **JSON** | парсер уже є в Godot; дерево виглядає як дерево; всі інструменти його знають | коми й дужки; при додаванні в кінець масиву міняється ще й попередній рядок |
| Свій текстовий формат | найкрасивіші diff | ще один парсер, екранування, помилки при ручному редагуванні |

Обираємо **JSON зі строгим канонічним форматуванням** (§4). Власний формат можна додати пізніше
лише як «вигляд для читання», не для зберігання.

## 3. Структура

### 3.1 Верхній рівень

```json
{
	"format": 1,
	"uses": { ... },
	"variables": [ ... ],
	"events": [ ... ]
}
```

| Поле | Що це |
|---|---|
| `format` | Версія формату файлу (ціле). Зростає лише при несумісних змінах |
| `uses` | Що аркуш використовує: типи, файли, плагіни (§3.5) |
| `variables` | Глобальні змінні аркуша |
| `events` | Блоки верхнього рівня (§3.2) |

### 3.2 Блоки

Кожен елемент `events` або `children` — це блок одного з видів:

| `type` | Що це | Поля |
|---|---|---|
| `"event"` (за замовчуванням, поле можна не писати) | Подія | `id`, `conditions`, `actions`, `children`, `or`, `disabled` |
| `"group"` | Група подій (П18) | `id`, `name`, `description`, `active`, `children` |
| `"comment"` | Коментар | `id`, `text`, `color` |
| `"variable"` | Локальна змінна (діє в батьківській події/групі та нижче) | `id`, `name`, `var_type`, `value`, `static` |
| `"include"` | *Пізніше:* підключити інший аркуш | `id`, `sheet` |
| `"function"` | *Пізніше:* функція аркуша | `id`, `name`, `params`, `children` |

### 3.3 Умови й дії

Кожна умова чи дія — **один рядок** JSON:

```json
{"ace": "var.Enemy.health.compare", "on": "Enemy", "params": {"op": "<=", "value": "0"}}
```

| Поле | Що це |
|---|---|
| `ace` | id з реєстру ACE (`ace-format.md` §2.1) |
| `on` | Тип або сімейство, для якого виконується. Немає поля = системний ACE |
| `behavior` | Ім'я behavior на типі, якщо ACE належить behavior (`"Platformer"`) |
| `params` | Значення параметрів **за назвою** (`ace-format.md` §2.3) |
| `invert` | `true` для інвертованої умови (П4) |
| `disabled` | `true` — вимкнено (сіре в аркуші, не компілюється) |

**Значення параметрів — завжди рядки:**
- для параметрів-виразів (`number`, `text`, `bool`, `color`, `any`) — текст виразу з
  `expressions.md`. Тому текстовий літерал виглядає як `"value": "\"Перемога!\""`: зовнішні лапки
  належать JSON, внутрішні — виразу;
- для вибору (`choice`, `comparison`, `object_type`, `input_action`, `key`…) — значення варіанта;
- для файлів — шлях `res://...` (а UID зберігається в `uses.files`, §3.5).

**Структурні умови** (Else, For each, Repeat, While, Trigger once, Pick all) записуються як
звичайні системні умови з особливими id: `system.else`, `system.for_each`,
`system.trigger_once`… Компілятор знає їх окремо, а формат файлу — ні.

### 3.4 id блоків

- Кожен блок має `id`: 6 символів `[a-z0-9]`, випадковий, унікальний у межах аркуша.
- **id не змінюється**, коли події переставляють, вставляють вище чи переносять у групу.
- Використовується для: зв'язку рядків згенерованого коду з подіями (`# @event a1b2c3`),
  точок зупинки, закладок і коментарів до подій.
- При вставці з буфера й дублюванні id генеруються заново.
- Номери подій («Подія 5»), які бачить користувач, рахуються при показі і у файлі не зберігаються.

### 3.5 `uses` — залежності

```json
"uses": {
	"types": {
		"Player": "uid://c8r1x0vq2m4hp",
		"Coin": "uid://b2kq7d1j5n0aw"
	},
	"files": {
		"res://sounds/coin.ogg": "uid://dw3p0m8k1q2zs"
	},
	"plugins": ["platformer_pack"]
}
```

- `types` — типи, згадані в аркуші (у полях `on` і всередині виразів), з UID їхніх сцен.
  Якщо сцену перейменували чи перенесли, тип знаходиться за UID.
- `files` — файли з параметрів. Якщо шлях більше не існує, а UID знаходиться, шлях
  виправляється при наступному збереженні (так само робить сам Godot у `.tscn`).
- `plugins` — плагіни, чиї ACE використовуються. Якщо плагіна немає, редактор одразу каже,
  який встановити.
- `uses` **перераховується при кожному збереженні** з вмісту аркуша, вручну його не редагують.
- Через `uses` завантажувач повідомляє Godot про залежності. Тоді перейменування у файловій
  панелі й експорт працюють без додаткових дій.

### 3.6 Змінні

```json
{"name": "Score", "var_type": "number", "value": "0"}
```

`var_type`: `number`, `text`, `bool`, `list`, `dictionary`. `value` — початкове значення як
вираз-константа. Локальна змінна з `"static": true` зберігає значення між кадрами (як у Construct).

## 4. Канонічне форматування

Файл завжди пишеться однаково, хто б і як його не зберіг:

1. UTF-8 без BOM, переноси рядків `LF`, наприкінці — порожній рядок.
2. Відступи — табуляція (як у Godot).
3. **Порядок ключів фіксований схемою**, не алфавітний, щоб читалося природно: `id`, `type`,
   `name`, `or`, `conditions`, `actions`, `children`… Для умов/дій: `ace`, `on`, `behavior`,
   `params`, `invert`, `disabled`. Ключі всередині `params` — у порядку параметрів в описі ACE. Словники з довільними ключами
   (`uses.types`, `uses.files`) — за абеткою.
4. **Значення за замовчуванням не пишуться** (`"invert": false`, `"disabled": false`,
   `"type": "event"`, порожні `children`).
5. **Умова чи дія — один рядок.** Блок (подія, група) — багато рядків.
6. Не-ASCII текст пишеться як є (`"Перемога!"`), без `З...`.
7. Числа в JSON не використовуються: усі значення параметрів — рядки (§3.3), тож немає
   проблем з `3` чи `3.0`.

## 5. Приклад

Скорочений аркуш із прикладу `picking.md` §4.3 (події 2, 4, 6, 6.1, 7), плюс група й коментар:

```json
{
	"format": 1,
	"uses": {
		"types": {
			"Coin": "uid://b2kq7d1j5n0aw",
			"Enemy": "uid://cq0n5r2w8k3yt",
			"HUD": "uid://d1m7x4p0s9qve",
			"Player": "uid://c8r1x0vq2m4hp"
		}
	},
	"variables": [
		{"name": "Score", "var_type": "number", "value": "0"}
	],
	"events": [
		{
			"id": "k4m2qz",
			"type": "comment",
			"text": "Збирання монет і вороги"
		},
		{
			"id": "p7d0aa",
			"type": "group",
			"name": "Гравець",
			"children": [
				{
					"id": "a1b2c3",
					"conditions": [
						{"ace": "solid.on_collided", "on": "Player", "behavior": "Solid", "params": {"object": "Coin"}}
					],
					"actions": [
						{"ace": "node.destroy", "on": "Coin"},
						{"ace": "system.add_to_variable", "params": {"variable": "Score", "value": "1"}}
					]
				}
			]
		},
		{
			"id": "x9w3e1",
			"conditions": [
				{"ace": "var.Enemy.health.compare", "on": "Enemy", "params": {"op": "<=", "value": "0"}}
			],
			"actions": [
				{"ace": "node.destroy", "on": "Enemy"}
			]
		},
		{
			"id": "r5t6y7",
			"conditions": [
				{"ace": "system.compare_variable", "params": {"variable": "Score", "op": ">=", "value": "10"}}
			],
			"children": [
				{
					"id": "u8i9o0",
					"conditions": [
						{"ace": "system.trigger_once"}
					],
					"actions": [
						{"ace": "auto.Label.text.set", "on": "HUD", "params": {"value": "\"Перемога!\""}}
					]
				}
			]
		},
		{
			"id": "z2x3c4",
			"conditions": [
				{"ace": "system.else"}
			],
			"actions": [
				{"ace": "auto.Label.text.set", "on": "HUD", "params": {"value": "\"Монети: \" & Score"}}
			]
		}
	]
}
```

*id ACE тут ілюстративні; остаточний список з'явиться разом із провайдерами на етапі 2.*

Як виглядає diff, коли користувач змінив «10 монет» на «20»:

```diff
-						{"ace": "system.compare_variable", "params": {"variable": "Score", "op": ">=", "value": "10"}}
+						{"ace": "system.compare_variable", "params": {"variable": "Score", "op": ">=", "value": "20"}}
```

## 6. Як аркуш стає кодом

- Аркуш прив'язаний до рівня через ноду-раннер у сцені. Скрипт цієї ноди — **сам файл
  `.eventsheet`**: завантажувач Godot для `.eventsheet` повертає скомпільований GDScript.
- Коли редактор просить модель аркуша (тип `EventSheet`), той самий завантажувач повертає
  модель для редагування.
- При збереженні аркуша редактор перекомпілює скрипт і оновлює його в пам'яті. Запущена
  з редактора гра одразу отримує нову версію.
- **Експорт:** плагін експорту замінює кожен `.eventsheet` скомпільованим GDScript (механізм
  remap, як Godot робить з `.tscn` → `.scn`). Компілятор у зібрану гру не потрапляє.
- *Це гіпотеза для перевірки на етапі 2.* Запасний варіант: згенеровані `.gd` у кеші
  `.godot/eventsheets/`, які плагін експорту додає в гру.

## 7. Помилки й сумісність

| Ситуація | Що відбувається |
|---|---|
| Невідомий ACE (немає плагіна) | Рядок червоний: «Невідома дія `foo.bar` — встановіть плагін `X`». Дані зберігаються як є, аркуш не компілюється |
| Невідоме поле (з новішої версії) | Зберігається як є, в кінці об'єкта |
| ACE з `deprecated` | Мігрується при відкритті (`ace-format.md` §2.1), у статусному рядку — повідомлення |
| Старіший `format` | Мігрується по кроках (1 → 2 → 3); перед першим збереженням — резервна копія `.eventsheet.bak` |
| Новіший `format` | Відкривається лише для читання: «Створено новішою версією рушія» |
| Маркери конфлікту git (`<<<<<<<`) | Не відкривається; повідомлення, де саме конфлікт |
| Зламаний JSON | Не відкривається; номер рядка й колонки помилки |
| Тип перейменовано (Player → Hero) | Редактор оновлює `on` і **імена у виразах** (через парсер з `expressions.md`, не пошуком тексту) |

## 8. Відкриті питання

1. Гіпотеза з §6 (`.eventsheet` завантажується як Script). Перевірити на прототипі, що
   Godot нормально працює з таким скриптом: інспектор, перезавантаження, експорт.
2. Чи потрібен окремий файл налаштувань аркуша (масштаб, згорнуті групи, закладки)?
   Пропоную тримати це **поза** аркушем, у `.godot/` (кеш редактора), щоб згортання групи не
   змінювало файл і не потрапляло в git.
3. Розмір: аркуш на 5000 подій — перевірити швидкість відкриття й збереження.
4. Чи дозволяти кілька аркушів на одну сцену, чи один аркуш + `include`.

## 9. Тести (специфікація поведінки)

| # | Дано | Очікуємо |
|---|---|---|
| S1 | будь-який аркуш: відкрити → зберегти без змін | файл байт у байт той самий |
| S2 | змінити один параметр | у diff змінився рівно один рядок |
| S3 | перемістити подію вище | змінились лише рядки переміщеної події та коми сусідів; id ті самі |
| S4 | аркуш з ACE невідомого плагіна → відкрити → змінити іншу подію → зберегти | рядок невідомого ACE на місці, без змін |
| S5 | файл з невідомим полем | поле збережене |
| S6 | перейменувати `coin.ogg` у файловій панелі Godot | шлях у параметрі й `uses.files` оновлено |
| S7 | перейменувати тип Player → Hero | `on` і вирази (`Player.X` → `Hero.X`) оновлено; текст `"Player"` у лапках **не** змінено |
| S8 | скопіювати 2 події й вставити в інший аркуш | події на місці, id нові, `uses` нового аркуша доповнено |
| S9 | файл з `"format": 0` | мігрований, створено `.bak` |
| S10 | файл з `"format": 99` | лише читання, попередження |
| S11 | файл з маркерами конфлікту git | не відкрито, показано рядок конфлікту |
| S12 | текст `"Перемога!"` | у файлі кирилиця як є, не `\u...` |
| S13 | експорт гри з аркушем | гра працює; компілятора в експорті немає |
| S14 | згорнути групу в редакторі | файл аркуша не змінився |
