# Дизайн: picking (вибірка інстансів) в event sheets

> Статус: **чернетка v0.1**. Етап 1 дорожньої карти (`docs/ROADMAP.md`).
> Мета документа — однозначно описати, *які інстанси* бачить кожна умова й дія,
> і *у що це компілюється* в GDScript. Код тут — ескізи; вони стануть тестами
> й реалізацією на етапі 2 і ще не запускались.

## 0. Простими словами

У Construct ти пишеш: «Enemy: health ≤ 0 → Enemy: знищити». Знищуються **не всі** вороги,
а тільки ті, у кого здоров'я ≤ 0. Умова «відібрала» (pick) частину ворогів, і дія
працює лише з ними. Це і є picking.

У звичайному коді Godot так не буває: треба самому написати цикл по всіх ворогах
і `if`. Наш компілятор пише цей цикл за користувача.

## 1. Глосарій

| Термін | Що це | В коді |
|---|---|---|
| **Тип** | «Вид» об'єкта: Player, Enemy, Coin. Одна сцена `.tscn` = один тип | група Godot з назвою типу |
| **Сімейство** | Кілька типів під однією назвою (Enemies = Slime + Bat) | ще одна група Godot |
| **Інстанс** | Конкретна копія типу на рівні | нода (корінь сцени-типу) |
| **Вибірка** (SOL, Selected Object List) | Для кожного типу: які інстанси зараз обрані | об'єкт `EsSol` |
| **Подія** | Рядок аркуша: умови → дії (+ підподії) | функція `_event_N` |
| **Підподія** | Подія всередині іншої; бачить вибірку батька | функція `_event_N_M` |
| **Умова інстансу** | Фільтрує інстанси типу («Enemy: health ≤ 0») | `sol.filter(...)` |
| **Системна умова** | Просто так/ні, нікого не фільтрує («Score ≥ 10») | `if not (...): return false` |
| **Тригер** | Умова-подія, що «стається» («Player зіткнувся з Coin») | обробник сигналу |
| **Псевдотригер** | Тригер, який перевіряється раз на тік («Натиснуто клавішу») | `Input.is_action_just_pressed` |
| **Дія інстансу** | Виконується для кожного обраного інстансу типу | цикл `for` |
| **Системна дія** | Виконується один раз («Score += 1») | один рядок |

## 2. Правила вибірки

### П1. Старт: обрано всіх
Кожна подія верхнього рівня починає з вибірки, де **для кожного типу обрані всі інстанси**.
Технічно «всі» зберігається як *відсутність запису* для типу, тому список інстансів не
будується, поки він не потрібен.

### П2. Умови інстансу звужують вибірку
Умови виконуються **по черзі, зверху вниз**. Кожна умова інстансу залишає у вибірці свого
типу лише ті інстанси, для яких вона істинна. Наступна умова працює вже з меншим списком.
Порядок має значення: «Pick nearest» після фільтра ≠ фільтр після «Pick nearest».

### П3. Порожня вибірка = подія не спрацювала
Якщо після якоїсь умови інстансу у вибірці типу не лишилось нікого, або системна умова
хибна, подія **зупиняється**: дії й підподії не виконуються, решта умов не перевіряється.

### П4. Інвертована умова
Інвертована умова інстансу залишає тих, для кого умова **хибна**.
Інвертована системна умова — просто `not`. Тригер інвертувати не можна (помилка компіляції).

### П5. Дії інстансу йдуть по обраних
Дія над типом X виконується для кожного обраного інстансу X. Якщо X не згадувався в умовах,
обрані всі (П1). Дії виконуються **по черзі**: дія 1 для всіх обраних, потім дія 2 для всіх.
Системна дія виконується один раз.

### П6. Вирази в діях
- Вираз того самого типу, над яким дія (`Enemy: встановити X = Enemy.X + 1`), бере
  **поточний інстанс** циклу.
- Вираз іншого типу (`Enemy: дивитись на Player`) бере **перший обраний** інстанс того типу.
- Якщо в іншого типу немає жодного обраного інстансу, подія **не виконується** (як П3),
  а редактор показує попередження. *Свідома відмінність від Construct, де вираз мовчки
  повертає 0; див. §6.*
- «Pairing» з Construct (однакова кількість A і B, тож їх розбивають на пари) — **поки ні**, див. §7.

### П7. Створення інстансу обирає його
Дія «Створити Bullet» (або «Player: створити Bullet» — по одному на кожного обраного Player)
робить вибірку Bullet **рівною лише щойно створеним** до кінця події, включно з підподіями.
Тригер «При створенні» для нового інстансу спрацьовує **одразу**, під час дії створення,
і нові інстанси до цього моменту вже стоять на своїх позиціях.

### П8. Знищені інстанси зникають з вибірки
«Знищити» викликає `queue_free()` (Godot видаляє ноду в кінці кадру). Вибірка **ніколи не
повертає** інстанси, які вже знищені або позначені на знищення, тож наступні події їх не бачать.

### П9. Підподії успадковують вибірку
Підподія отримує **копію** вибірки батька *після* його дій (з урахуванням П7) і звужує вже її.
Зміни вибірки в підподії не впливають ні на батька, ні на сусідні підподії.
Підподії виконуються після всіх дій батька, по черзі.

### П10. Сусідні події незалежні
Кожна подія верхнього рівня стартує з «обрано всіх» (П1). Сусідні підподії стартують з
вибірки спільного батька. Звуження в одній події не «протікає» в наступну.

### П11. Else
`Else` прив'язаний до попередньої сусідньої події і виконується, якщо вона **не спрацювала**
(П3). Вибірка Else — вибірка батька, тобто як у попередньої події *до* її умов.
Else може мати власні умови (виходить «else if»). Else без попередньої сусідньої події,
або після події з тригером, дає помилку компіляції.

### П12. OR-блок
Подія з позначкою «АБО» спрацьовує, якщо істинна **хоча б одна** умова. Кожна умова
перевіряється на вибірці *на вході* події (не на звуженій попередньою). Для кожного типу
вибірка = **об'єднання** інстансів з усіх істинних умов цього типу, у порядку першої появи.
Тип, згаданий лише в хибних умовах, зберігає вибірку входу. *Перевірити проти Construct, §7.*

### П13. For each
«Для кожного X» запускає підподії **окремо для кожного** обраного X, і на кожній ітерації
у вибірці X лише один інстанс. «Для кожного X (впорядковано за виразом)» спершу сортує.
Список для обходу береться на початку циклу. Створені під час циклу X не обходяться,
а знищені пропускаються (П8).

### П14. Wait (чекати)
«Чекати N секунд» призупиняє решту дій і підподій цієї події. Після паузи **вибірка
зберігається** такою, якою була, мінус знищені за цей час (П8). Інші події тим часом
працюють як звичайно. Якщо рівень закрили під час очікування, решта просто не виконується
(без помилки).

### П15. Trigger once while true (лише раз, поки істинно)
Остання умова в події. Подія спрацьовує, якщо всі попередні умови істинні **зараз** і не були
істинні на **попередньому тіку**. Стан зберігається **на подію**, не на інстанс (як у Construct).
Якщо подію в попередньому тіку взагалі не перевіряли (батько не спрацював), це рахується як
«не були істинні».

### П16. Тригери
- Тригер — **завжди перша** умова події (інакше помилка компіляції).
- Справжній тригер (сигнал: зіткнення, «при створенні», таймер, анімація закінчилась)
  запускає подію **поза звичайним порядком тіку**, в момент сигналу.
- Вибірка в тригері: як П1 (обрано всіх), але **типи-учасники тригера обрані рівно тими
  інстансами, що беруть участь**. «Player зіткнувся з Coin» обирає саме цього Player і саму цю Coin.
- Псевдотригер (клавіша натиснута, «кожні N секунд») — звичайна умова, що перевіряється у
  своїй черзі в тіку. Для користувача різниці немає.
- MVP: тригер лише в подіях верхнього рівня (можна всередині груп). Тригери в підподіях — §7.

### П17. Сімейства
Сімейство має **свою, окрему** вибірку. Звуження Enemies не змінює вибірку Slime і навпаки
(як у Construct). Якщо в одній події треба розрізнити два інстанси одного типу
(Enemy зіткнувся з Enemy), один бік задають через сімейство.

### П18. Групи подій
Групи лише організовують аркуш і вмикаються/вимикаються. На вибірку не впливають:
подія в групі поводиться як подія верхнього рівня.

## 3. Модель виконання

- Аркуш прив'язаний до рівня (сцени). Компілятор генерує скрипт `<рівень>.events.gd`
  на ноді `EventSheetRunner`, яку редактор сам кладе в корінь рівня.
- Кожен кадр: `_process(delta)` викликає функції подій верхнього рівня **в порядку аркуша**
  (зверху вниз), включно з псевдотригерами.
- Справжні тригери підключаються в `_ready` до вже існуючих інстансів і до нових
  (через `SceneTree.node_added`).
- Інстанси шукаються в усьому дереві сцени (`get_nodes_in_group`). Тобто і об'єкти, що
  переходять між рівнями (UI, музика), видимі для аркуша.
- Тип = група, яку редактор записує в `.tscn` кореня сцени-типу. Користувач групи руками не створює.

## 4. У що це компілюється

### 4.1 Рантайм (ескіз)

Невелика бібліотека, з якою працює згенерований код. На етапі 2 це GDScript,
пізніше може переїхати в C++ модуль без зміни згенерованого коду.

```gdscript
class_name EsSol
extends RefCounted
## Вибірка: які інстанси кожного типу зараз обрані.
## Немає запису для типу = обрані всі (П1).

var _tree: SceneTree
var _picked: Dictionary = {}  # StringName -> Array (масиви не змінюються, лише замінюються)


func _init(tree: SceneTree) -> void:
	_tree = tree


## Копія для підподії (П9). Поверхнева: масиви ніколи не змінюються на місці.
func copy() -> EsSol:
	var c := EsSol.new(_tree)
	c._picked = _picked.duplicate()
	return c


## Живі обрані інстанси типу (П1, П8).
func get_picked(type: StringName) -> Array:
	var source: Array = _picked[type] if _picked.has(type) else _tree.get_nodes_in_group(type)
	return source.filter(_is_alive)


## Звузити вибірку типу умовою. false = нікого не лишилось (П2, П3).
func filter(type: StringName, keep: Callable) -> bool:
	var result := get_picked(type).filter(keep)
	_picked[type] = result
	return not result.is_empty()


## Обрати рівно ці інстанси (тригери П16, створення П7, for each П13).
func pick_only(type: StringName, instances: Array) -> void:
	_picked[type] = instances


## «Pick all»: знову обрати всіх.
func pick_all(type: StringName) -> void:
	_picked.erase(type)


## Перший обраний інстанс для виразу іншого типу (П6). null = нікого.
func first(type: StringName) -> Node:
	var list := get_picked(type)
	return null if list.is_empty() else list[0]


func _is_alive(node) -> bool:
	return is_instance_valid(node) and not node.is_queued_for_deletion()
```

`EsRunner` (база для згенерованого скрипта) дає: `new_sol()`, `spawn(scene, at)`
(П7: позиція встановлюється до `_ready`), `wait(seconds)` (П14: таймер-дитина раннера, тож
якщо рівень закрили, очікування тихо зникає) і `bind_trigger(type, signal, handler)` (П16).

### 4.2 Шаблони компіляції

**Звичайна подія** — функція, яка повертає «чи спрацювала» (потрібно для Else):

```gdscript
func _event_N(parent: EsSol) -> bool:
	<системні умови>                           # if not (...): return false
	var sol := parent.copy()
	<умови інстансу>                           # if not sol.filter(...): return false
	<дії>                                      # for x in sol.get_picked(&"X"): ...
	<підподії>                                 # _event_N_1(sol) ...
	return true
```

**Подія з Wait** — умови рахуються одразу (щоб Else знав результат), а дії йдуть в окрему
функцію-корутину, яку **не чекаємо**:

```gdscript
func _event_N(parent: EsSol) -> bool:
	...умови...
	_event_N_do(sol)       # без await: подія «спрацювала», решта виконається пізніше
	return true
```

**Else**: `if not _event_5(sol): _event_6(sol)`.

**For each**:

```gdscript
for enemy in sol.get_picked(&"Enemy"):
	var it := sol.copy()
	it.pick_only(&"Enemy", [enemy])
	_event_N_1(it)
```

**Trigger once** (П15): поле з номером кадру, коли подія востаннє була істинною.

```gdscript
var frame := Engine.get_process_frames()
var was_true := _once_N == frame - 1
_once_N = frame
if was_true:
	return false
```

### 4.3 Повний приклад

Аркуш рівня «Збирай монети»:

| # | Умови | Дії |
|---|---|---|
| 1 | Натиснуто дію «shoot» | Player: створити Bullet у позиції Player |
| 2 | Player зіткнувся з Coin *(тригер)* | Coin: знищити · Score += 1 |
| 3 | Bullet зіткнувся з Enemy *(тригер)* | Bullet: знищити · Enemy: health −= 1 · Enemy: сховати · Чекати 0.1 с · Enemy: показати |
| 4 | Enemy: health ≤ 0 | Enemy: знищити |
| 5 | Enemy: відстань до Player < 10 | Enemy: дивитись на Player |
| 6 | Score ≥ 10 | — |
| 6.1 | ↳ Лише раз, поки істинно | HUD: текст = «Перемога!» |
| 7 | Else | HUD: текст = «Монети: » & Score |

Згенерований код (так його і побачить користувач у «Показати код»):

```gdscript
# Згенеровано з level_1.eventsheet — не редагуй вручну, зміни зітруться.
extends EsRunner

const BULLET := preload("res://objects/bullet.tscn")

var score := 0           # глобальна змінна Score
var _once_6_1 := -1      # П15


func _ready() -> void:
	bind_trigger(&"Player", &"collided", _on_event_2)
	bind_trigger(&"Bullet", &"collided", _on_event_3)


func _process(_delta: float) -> void:
	var root := new_sol()
	_event_1(root)
	_event_4(root)
	_event_5(root)
	if not _event_6(root):
		_event_7(root)


# Подія 1: Натиснуто «shoot» → Player: створити Bullet
func _event_1(parent: EsSol) -> bool:
	if not Input.is_action_just_pressed(&"shoot"):
		return false
	var sol := parent.copy()
	var created := []
	for player in sol.get_picked(&"Player"):
		created.append(spawn(BULLET, player.global_position))
	sol.pick_only(&"Bullet", created)   # П7
	return true


# Подія 2: Player зіткнувся з Coin → Coin: знищити; Score += 1
func _on_event_2(player: Node, other: Node) -> void:
	if not other.is_in_group(&"Coin"):
		return
	var sol := new_sol()
	sol.pick_only(&"Player", [player])  # П16
	sol.pick_only(&"Coin", [other])
	for coin in sol.get_picked(&"Coin"):
		coin.queue_free()
	score += 1                          # системна дія: один раз


# Подія 3: Bullet зіткнувся з Enemy → ...; Чекати 0.1; ...
func _on_event_3(bullet: Node, other: Node) -> void:
	if not other.is_in_group(&"Enemy"):
		return
	var sol := new_sol()
	sol.pick_only(&"Bullet", [bullet])
	sol.pick_only(&"Enemy", [other])
	for b in sol.get_picked(&"Bullet"):
		b.queue_free()
	for enemy in sol.get_picked(&"Enemy"):
		enemy.health -= 1
	for enemy in sol.get_picked(&"Enemy"):
		enemy.visible = false
	await wait(0.1)                     # П14: вибірка зберігається
	for enemy in sol.get_picked(&"Enemy"):   # якщо ворога вже знищено — порожньо
		enemy.visible = true


# Подія 4: Enemy: health ≤ 0 → Enemy: знищити
func _event_4(parent: EsSol) -> bool:
	var sol := parent.copy()
	if not sol.filter(&"Enemy", func(enemy): return enemy.health <= 0):
		return false
	for enemy in sol.get_picked(&"Enemy"):
		enemy.queue_free()
	return true


# Подія 5: Enemy: відстань до Player < 10 → Enemy: дивитись на Player
func _event_5(parent: EsSol) -> bool:
	var sol := parent.copy()
	var player = sol.first(&"Player")   # П6: перший обраний
	if player == null:
		return false
	var near_player := func(enemy): return enemy.global_position.distance_to(player.global_position) < 10.0
	if not sol.filter(&"Enemy", near_player):
		return false
	for enemy in sol.get_picked(&"Enemy"):
		enemy.look_at(player.global_position)
	return true


# Подія 6: Score ≥ 10
func _event_6(parent: EsSol) -> bool:
	if not (score >= 10):
		return false
	var sol := parent.copy()
	_event_6_1(sol)
	return true


# Подія 6.1: Лише раз, поки істинно → HUD: текст = "Перемога!"
func _event_6_1(parent: EsSol) -> bool:
	var frame := Engine.get_process_frames()
	var was_true := _once_6_1 == frame - 1
	_once_6_1 = frame
	if was_true:
		return false
	var sol := parent.copy()
	for hud in sol.get_picked(&"HUD"):
		hud.text = "Перемога!"
	return true


# Подія 7: Else → HUD: текст = "Монети: " & Score
func _event_7(parent: EsSol) -> bool:
	var sol := parent.copy()
	for hud in sol.get_picked(&"HUD"):
		hud.text = "Монети: " + str(score)
	return true
```

Примітки до прикладу:
- Код однаковий для 2D і 3D: `global_position`, `look_at`, `visible` є і в `Node2D`, і в `Node3D`.
  Різницю між 2D і 3D несуть ACE (`docs/design/ace-format.md`), а не picking.
- Сигнал `collided(other)` дає behavior (Solid/Platformer/Character), бо в
  `CharacterBody2D/3D` такого сигналу немає. Це питання ACE/behaviors, не picking.
- Подія 3 — тригер, тому її обробник сам може `await`: Else до неї не прив'язаний.

## 6. Відмінності від Construct (свідомі)

| Що | Construct | Ми | Чому |
|---|---|---|---|
| Вираз типу без обраних інстансів | повертає 0 | подія не виконується + попередження | 0 тихо ламає логіку; новачку важко знайти причину |
| Нові інстанси в наступних подіях | недоступні до кінця події верхнього рівня | доступні одразу | так працює дерево Godot; простіше пояснити |
| «Pairing» | є | поки немає | рідко потрібен, ускладнює модель |
| Тригер у підподії | дозволено | поки ні | MVP |

## 7. Відкриті питання

1. `_process` чи `_physics_process` для подій? Зараз `_process`; behaviors з фізикою
   працюють у своєму `_physics_process`. Перевірити на 3D-персонажі, чи немає тремтіння.
2. OR-блок (П12): як саме Construct обирає тип, згаданий лише в хибних умовах? Перевірити в C3.
3. Тригери в підподіях: коли і як.
4. Pairing — чи потрібен.
5. Два інстанси одного типу в одній умові (Enemy ↔ Enemy) — чи досить сімейств (П17).
6. Контейнери Construct (створюються/знищуються/обираються разом) — потрібні? Можна імітувати
   дочірніми нодами.
7. Функції аркуша: передавати вибірку («copy picked») чи ні.
8. Кілька аркушів на рівень (include) — порядок виконання.
9. Продуктивність: `get_nodes_in_group` і `filter` створюють масиви щокадру. Ціль —
   1000 інстансів при 60 FPS; виміряти на етапі 2, кешування вибірки «всіх» на тік — якщо треба.
10. Помилки виконання: зв'язок рядка GDScript з подією аркуша (коментар `# Подія N` у
    згенерованому коді — початок; окремий документ).
