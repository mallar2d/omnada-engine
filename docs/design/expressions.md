# Дизайн: мова виразів

> Статус: **чернетка v0.1**. Етап 1 дорожньої карти (`docs/ROADMAP.md`).
> Пов'язані документи: `picking.md` (П6 — який інстанс бере вираз), `ace-format.md`
> (вирази-ACE, типи параметрів). Код тут — ескізи; ще не запускались.

## 0. Простими словами

Вираз — це те, що користувач пише в полі параметра: `Player.X + 10`, `"Монети: " & Score`,
`random(1, 6)`, `health <= 0 ? "мертвий" : "живий"`. Це **не** програмування: немає
присвоєнь, циклів, функцій, лише «порахуй значення».

Синтаксис майже як у Construct, щоб його люди одразу впізнали. Компілятор перекладає вираз у
GDScript і **перевіряє його ще в редакторі**: помилку видно червоним одразу, з підказкою, а не
під час гри.

## 1. Цілі

1. **Знайомо для Construct.** `Sprite.X`, `&` для склеювання тексту, `=` і `<>` для порівняння,
   `random()`, `choose()`, `dt`, `loopindex`.
2. **Без пасток GDScript.** `7 / 2` дає `3.5`, а не `3`. Число в тексті пишеться як `3`, а не `3.0`.
3. **Помилки зрозумілі новачку:** де саме, чому, і що, ймовірно, малося на увазі.
4. **Безпека.** Текст користувача ніколи не вставляється в GDScript «як є». Вираз проходить
   розбір, перевірку і лише потім генерується код. Тому аркуш, скачаний з інтернету, не може
   підсунути довільний GDScript через поле виразу.
5. **Автодоповнення** знає типи об'єктів, їхні змінні, behaviors і вирази-ACE.

## 2. Типи значень

| Тип | Як пишеться | У GDScript | Примітка |
|---|---|---|---|
| **число** | `3`, `-2.5`, `1e3` | `float` | Завжди дробове, як у Construct. Там, де Godot вимагає ціле, компілятор сам додасть `int()` |
| **текст** | `"Привіт"`, `"Він сказав ""так"""` | `String` | Лапки всередині подвоюються, як у Construct |
| **так/ні** | `true`, `false`, результат порівняння | `bool` | |
| **колір** | `rgb(255, 0, 0)`, `rgba(...)` | `Color` | |
| **список**, **словник** | лише змінні цих типів | `Array`, `Dictionary` | Доступ через вирази-ACE: `Inventory.At(0)`, `Stats.Get("hp")` |
| **будь-що** | результат автогенерованого ACE без відомого типу | `Variant` | Редактор показує жовте попередження |

Неявних перетворень мало, і всі передбачувані:
- `&` перетворює будь-що на текст (числа без зайвого `.0`).
- Число туди, де потрібне ціле, обрізається.
- **Ніяких** інших: `"5" + 1` дає помилку з підказкою «для склеювання тексту використовуй `&`;
  щоб перетворити текст на число — `float("5")`».

## 3. Синтаксис

### 3.1 Оператори (від найслабшого до найсильнішого)

| Рівень | Оператори | Значення | Асоціативність |
|---|---|---|---|
| 1 | `умова ? a : b` | якщо умова, то a, інакше b | справа наліво |
| 2 | `or` | або | зліва направо |
| 3 | `and` | і | зліва направо |
| 4 | `not` | не (префікс) | — |
| 5 | `=` `==` `<>` `!=` `<` `<=` `>` `>=` | порівняння, результат так/ні | **без ланцюжків**: `a < b < c` — помилка |
| 6 | `&` | склеювання тексту | зліва направо |
| 7 | `+` `-` | додавання, віднімання | зліва направо |
| 8 | `*` `/` `%` | множення, ділення, остача | зліва направо |
| 9 | `-` (унарний) | мінус | — |
| 10 | `^` | степінь | справа наліво (`-2^2 = -4`, `2^3^2 = 512`) |
| 11 | `.` `( )` | доступ до виразу об'єкта, виклик | зліва направо |

Рішення, які відрізняються від Construct:
- **Логіка словами `and`, `or`, `not`.** У Construct `&` означає і «і», і склеювання тексту,
  і це плутає. У нас `&` лише склеює.
- **`=` і `==` обидва означають «дорівнює»**, `<>` і `!=` — «не дорівнює». Присвоєнь у виразах
  немає, тож `=` ні з чим не сплутати.
- Десятковий роздільник — **завжди крапка**, аргументи розділяються комою, незалежно від мови
  інтерфейсу (в українській звично `2,5`, але тоді `max(2,5)` стало б неоднозначним).

### 3.2 Імена

Пошук імені йде в такому порядку:
1. **Локальна змінна** події (і її батьків).
2. **Глобальна змінна** (`Score`).
3. **Системний вираз** (`dt`, `time`, `random`, `loopindex`…).
4. **Тип або сімейство** (`Player`, `Enemies`). Після нього обов'язково йде `.` або `(`.

Редактор не дозволяє створити змінну з тим самим ім'ям, що й тип або системний вираз.
Імена **нечутливі до регістру**: `player.x` = `Player.X`. Редактор сам виправляє написання
на канонічне при виході з поля.

Ключові слова й назви виразів — англійські в будь-якій мові інтерфейсу (рішення з
`ace-format.md` §7.2). Автодоповнення показує опис мовою інтерфейсу.

### 3.3 Вирази об'єктів

| Запис | Що значить |
|---|---|
| `Enemy.X` | Вираз-ACE `X` для інстансу Enemy (який саме — §4) |
| `Enemy.health` | Змінна інстансу |
| `Enemy.Platformer.Speed` | Вираз behavior |
| `Enemy.DistanceTo(0, 0)` | Вираз-ACE з параметрами |
| `Enemy(2).X` | Третій (рахунок з 0) **з обраних** інстансів |
| `Enemy.Count` | Скільки Enemy на рівні **всього** |
| `Enemy.PickedCount` | Скільки Enemy **обрано** в цій події |

### 3.4 Граматика

```ebnf
expr        = ternary ;
ternary     = or_expr [ "?" expr ":" expr ] ;
or_expr     = and_expr { "or" and_expr } ;
and_expr    = not_expr { "and" not_expr } ;
not_expr    = "not" not_expr | compare ;
compare     = concat [ cmp_op concat ] ;
cmp_op      = "=" | "==" | "<>" | "!=" | "<" | "<=" | ">" | ">=" ;
concat      = additive { "&" additive } ;
additive    = multiplic { ( "+" | "-" ) multiplic } ;
multiplic   = unary { ( "*" | "/" | "%" ) unary } ;
unary       = "-" unary | power ;
power       = postfix [ "^" unary ] ;
postfix     = primary { "." name [ args ] } ;
primary     = number | text | "true" | "false"
            | name [ args ]                     (* змінна, системний вираз, Тип(індекс) *)
            | "(" expr ")" ;
args        = "(" [ expr { "," expr } ] ")" ;
name        = letter { letter | digit | "_" } ;
number      = digit { digit } [ "." digit { digit } ] [ ( "e" | "E" ) [ "-" ] digit { digit } ] ;
text        = '"' { any_char_except_quote | '""' } '"' ;
```

`power` бере праву частину як `unary`, тому `2^-1` працює, а `-2^2` = `-(2^2)`.

## 4. Який інстанс бере вираз (зв'язок з picking)

Це правило П6 з `picking.md`, тут детальніше:

| Де стоїть вираз | `Enemy.X` означає |
|---|---|
| Параметр дії над Enemy | **поточний** Enemy циклу (кожен Enemy отримує своє значення) |
| Параметр умови-фільтра над Enemy | **поточний** Enemy, що перевіряється |
| Будь-де інде (дія над іншим типом, системна умова/дія) | **перший обраний** Enemy |
| `Enemy(i).X` | i-й обраний, де завгодно |

**Параметри обчислюються для кожного інстансу окремо.** «Enemy: встановити X = `random(0, 100)`»
дає кожному ворогу **різне** випадкове X (як у Construct).

**Немає обраного інстансу.** Якщо вираз бере «першого обраного», а обраних немає, подія не
виконується (П6), і редактор попереджає. Для `Enemy(i)` з індексом поза межами індекс
відомий лише під час гри, тому вираз повертає значення за замовчуванням (`0`, `""`, `false`),
а в налагоджувальний вивід іде попередження з номером події.

## 5. Системні вирази (мінімальний набір для етапу 2)

| Група | Вирази |
|---|---|
| Математика | `abs` `min` `max` `clamp` `floor` `ceil` `round` `sqrt` `sin` `cos` `tan` `atan2` `lerp` `distance(x1,y1,x2,y2)` `distance3d(...)` `angle(x1,y1,x2,y2)` `pi` |
| Випадковість | `random(a)` → [0, a), `random(a, b)` → [a, b), `randomint(a, b)` → ціле в [a, b], `choose(a, b, …)` |
| Перетворення | `int(x)` (обрізає), `float(t)`, `str(x)` |
| Текст | `len` `left` `right` `mid` `find` `replace` `upper` `lower` `trim` `tokenat` `tokencount` `newline` |
| Час | `dt` (секунд з минулого кадру), `time` (секунд від старту гри) |
| Цикли | `loopindex` (найближчий цикл), `loopindex("ім'я")` |
| Колір | `rgb(r,g,b)` `rgba(r,g,b,a)` (0–255) |

Системні вирази теж описуються як ACE (`applies_to = "system"`, `kind = "expression"`), тож
плагіни можуть додавати свої.

## 6. Компіляція

### 6.1 Конвеєр

```
текст → токени → дерево (AST) → перевірка (імена, типи, контекст) → GDScript
```

1. **Токенізатор:** числа, тексти, імена, оператори. Позиція кожного токена запам'ятовується,
   щоб показати помилку в потрібному місці поля.
2. **Парсер** будує дерево за граматикою §3.4 (Pratt-парсер — простий і дає точні помилки).
3. **Перевірка:** кожне ім'я знаходиться (§3.2), типи сходяться (§2), вираз об'єкта отримує
   контекст (§4). На цьому етапі з'являються всі помилки й попередження.
4. **Генерація:** обхід дерева. Дужки ставляться за пріоритетом GDScript, тексти заново
   екрануються, імена беруться лише з таблиць реєстру, а не з тексту користувача.

Генерація ніколи не видає GDScript, який не скомпілюється: усе, що могло б зламатися, ловить
перевірка на кроці 3.

### 6.2 Як що перекладається

| Вираз | GDScript | Чому |
|---|---|---|
| `a / b` | `a / b`, але якщо хоч один бік може бути `int` (змінна зі скрипта користувача) — `float(a) / b` | `7 / 2` має дати `3.5` |
| `a % b` | `fmod(a, b)` | у GDScript `%` лише для цілих |
| `a ^ b` | `pow(a, b)` | |
| `a = b`, `a <> b` | `a == b`, `a != b` | |
| `c ? a : b` | `(a if c else b)` | |
| `"x" & n` | `"x" + Es.text(n)` | `Es.text(3.0)` → `"3"`, а не `"3.0"` |
| `Enemy.X` (поточний) | `enemy.global_position.x` | шаблон ACE `X` |
| `Player.X` у дії над Enemy (перший обраний) | `player.global_position.x` + перед першим використанням `var player = sol.first(&"Player")` і перевірка на `null` | П6, приклад — подія 5 у `picking.md` §4.3 |
| `Enemy(i).X` | `Es.at(sol, &"Enemy", int(i), 0.0)`… | значення за замовчуванням поза межами |
| `Enemy.Count` | `count(&"Enemy")` | метод раннера |
| `Enemy.PickedCount` | `sol.get_picked(&"Enemy").size()` | |
| `random(a, b)` | `randf_range(a, b)` | |
| `randomint(a, b)` | `float(randi_range(int(a), int(b)))` | |
| `choose(a, b, c)` | `[a, b, c].pick_random()` | |
| `dt`, `time` | `dt`, `time` (поля раннера, оновлюються в `_process`) | |
| `loopindex` | `sol.loop_index()` | індекс циклу живе у вибірці й копіюється в підподії |
| `Score` | `score` | глобальна змінна — поле раннера |

### 6.3 Приклад

Дія «HUD: встановити текст» з виразом:

```
"Ворогів: " & Enemy.PickedCount & " / " & Enemy.Count & (Score >= 10 ? " — перемога!" : "")
```

Компілюється в:

```gdscript
for hud in sol.get_picked(&"HUD"):
	hud.text = "Ворогів: " + Es.text(sol.get_picked(&"Enemy").size()) + " / " \
			+ Es.text(count(&"Enemy")) + (" — перемога!" if score >= 10 else "")
```

## 7. Помилки й підказки

Кожна помилка має **місце** (підкреслення в полі), **причину** і, де можна, **підказку**.
Тексти перекладаються.

| Що написано | Повідомлення |
|---|---|
| `Scor + 1` | Невідоме ім'я `Scor`. Може, `Score`? |
| `"Монети: " + Score` | Текст і число не додаються через `+`. Щоб склеїти, використовуй `&` |
| `Player.Xx` | У Player немає `Xx`. Може, `X`? |
| `Player.Jump` | `Jump` — це дія, а не значення. Дії додаються в стовпець дій |
| `max(1)` | `max` потребує щонайменше 2 значення |
| `1 < x < 5` | Порівняння не можна ставити ланцюжком. Напиши `1 < x and x < 5` |
| `(1 + 2` | Не вистачає `)` |
| `x > 0 ? 1` | Після `?` потрібна `:` з другим варіантом |
| `health ? 1 : 0` | Умова має бути так/ні. Може, `health > 0`? |
| `"текст` | Текст не закритий лапками |

Підказка «може, …?» шукає найближче ім'я (відстань Левенштейна ≤ 2) серед доступних у цьому місці.

## 8. Автодоповнення

- Порожнє поле або початок імені: змінні, системні вирази, типи — з іконками й описом.
- Після `Тип.`: вирази-ACE цього типу (з урахуванням 2D/3D), його змінні, його behaviors.
- Після `Тип.Behavior.`: вирази behavior.
- Усередині `(…)`: підказка з назвами й типами параметрів поточного виразу.
- Пошук нечіткий і знаходить англійські ключові слова з `keywords` ACE (`ace-format.md` §2.1).

## 9. Відкриті питання

1. **Локальні змінні й Wait.** Чи зберігати значення локальних змінних після `Wait`, як вибірку
   (П14)? Пропоную так. Перевірити, як це робить Construct.
2. **Локальні змінні в коді:** поле раннера (просто, але не працює з кількома одночасними Wait)
   чи передавати разом з вибіркою (`sol`)? Схиляюсь до `sol`.
3. **`Enemy(i)` поза межами:** значення за замовчуванням + попередження (§4) чи зупинка події?
4. **Списки й словники:** лише вирази-ACE (`Inventory.At(0)`) чи ще й `Inventory[0]`? Для ACE
   на змінних-списках у `ace-format.md` знадобиться `applies_to = "value:list"`.
5. **Тексти з `\n`.** Чи підтримувати екранування в стилі програмістів поруч з `newline`?
6. **Цілі числа.** Чи потрібен окремий тип «ціле» для змінних, чи досить «число» + `int()`?
